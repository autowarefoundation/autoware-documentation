# Sensing

This page describes the interface of the Sensing component. See the [Sensing component design](../../components/sensing/index.md) for the concepts.

The Sensing component takes the data of the sensor drivers and preprocesses it for Perception and Localization. The sensor kit of a vehicle launches the drivers and the preprocessing. The topic names below come from [`sample_sensor_kit_launch`](https://github.com/autowarefoundation/autoware_launch/tree/main/sensor_kit/sample_sensor_kit_launch) and the launch files of [`autoware_sensing_launch`](https://github.com/autowarefoundation/autoware_launch/tree/main/autoware_universe_launch/autoware_sensing_launch). Another sensor kit can use other names for the driver topics.

Radar topics: No sensor kit in `autoware_launch` 0.53.0 launches a radar. The [`radar_tracks_postprocessor.launch.xml`](https://github.com/autowarefoundation/autoware_launch/blob/0.53.0/autoware_universe_launch/autoware_sensing_launch/launch/radar_tracks_postprocessor.launch.xml) launch file runs the noise filter and `autoware_radar_tracks_msgs_converter`. Its topic names are relative. If a sensor kit includes it in the namespace `/sensing/radar/<radar name>`, it reads `/sensing/radar/<radar name>/objects_raw` and publishes `/sensing/radar/<radar name>/detected_objects`. The Perception launch files read one topic, `/sensing/radar/detected_objects`, by default (the `input/radar` argument of [`object_recognition_lidar_radar.launch.xml`](https://github.com/autowarefoundation/autoware_launch/blob/0.53.0/autoware_universe_launch/autoware_perception_launch/launch/object_recognition/object_recognition_lidar_radar.launch.xml), for example). So a sensor kit must merge the objects of all radars into this topic. For example, the [`aip_xx1_gen2_launch`](https://github.com/tier4/aip_launcher/blob/f2401f29e1afdf7d504572e65a0e6790a1694a87/aip_xx1_gen2_launch/launch/radar.launch.xml) sensor kit of TIER IV merges its radars with `autoware_simple_object_merger`, and it relays the topic of a single radar with `topic_tools relay`.

Inputs marked "Not defined": Autoware 2.0.0 defines no Sensing topic for these inputs. The `autoware_component_interface_specs` package does not define them, no launch file in `autoware_launch` uses them, and the Sensing component has no outputs for them. A search of the Autoware 2.0.0 workspace found only these related topics:

- Ultrasonics: no topic, no node, and no launch file.
- Radar scan: the Nebula drivers of the Continental ARS548 and SRR520 radars publish `radar_msgs/msg/RadarScan` topics (for example `scan_raw`) in the namespace of the radar. No launch file in `autoware_launch` uses them.
- GNSS velocity: the u-blox driver of `sample_sensor_kit_launch` publishes `/sensing/gnss/ublox/fix_velocity` and `/sensing/gnss/ublox/navpvt`. The Sensing component does not process them. [Eagleye](https://github.com/autowarefoundation/autoware_launch/blob/0.53.0/autoware_universe_launch/autoware_localization_config/config/eagleye_config.param.yaml), an optional localization method, reads the GNSS velocity directly from `/sensing/gnss/ublox/navpvt`.
- GNSS acceleration: no topic, no node, and no launch file.
